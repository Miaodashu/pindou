# P0 稳定性加固交接

## 已完成

- 每格源颜色候选从最多 4 个收敛为最多 3 个，并增加回归测试。
- 为显示画布增加 8192 边长与 16M 像素预算，所有交互重绘统一通过 `requestAnimationFrame` 合并；大图 PNG 会明确按安全的像素/格密度导出并提示用户。
- 图纸与临摹图的防抖保存支持 `pagehide`、页面隐藏时立即 flush；并发保存使用版本号保护，失败会保留 `error` 状态并拒绝 Promise。
- 派生图纸、源图纸与关系记录在同一 IndexedDB 事务中提交；关系记录使用版本化 Zod Schema，并支持旧 `localStorage` 数据的一次性迁移与孤立源关系清理。
- OpenCV/Canvas E2E 改为单 worker；转换详情测试先展开折叠区域再断言运行时信息。
- 修正结构化转换交接文档中的领域术语，统一使用“色卡”。

## 验证

- `npm run check`：通过（22 个测试文件、73 项测试、类型检查、Lint、生产构建）。
- 完整 E2E 在最终断言调整前运行到 26/28 通过；两个失败均为 rAF 后立即读取 Canvas 像素导致的时序问题，断言已改为 `expect.poll`。
- v4→v5 IndexedDB 升级及旧派生关系迁移已在 Chromium 和 WebKit 的上述运行中通过。
- 最终 E2E 复跑受当前沙箱 `listen EPERM 127.0.0.1:4173` 与自动提权额度限制，未能启动测试服务器。

## 后续建议

- 当前方案限制单块 Canvas 的内存并降低大图导出密度，但尚未实现可视区域分块渲染；如继续提升 300×300 图纸的交互性能，下一步应引入 viewport/tile 渲染与分块导出。
